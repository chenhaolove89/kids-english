# 快乐学园：产品架构与分期实施

日期：2026-09-07。状态：完成源码调研；实现尚未委派。本文是实施设计，不代表功能已交付。

## 现状与判断

现有项目是 uni-app / Vue 3 / Vite 静态 H5，已有三科入口、英语词卡、语文识字、听音选择和数学动态出题。课程资源由 CSV 工具生成 JSON、图片和音频，适合保留。当前 package.json 仅配置 H5 开发和构建，不能据此声称小程序或 App 已可用。

目前课程主要按 L1–L4 难度组织，缺少年级、知识点、课时和学习记录。现有等级不等于小学年级，应保留其意义，另加年级维度。数学生成题目与判题在 practice.vue 中；音频封装直接依赖 Howler，含浏览器 document/AudioContext 行为。英语/语文挑战与数学允许答错重试，最终答对都会加分，当前分数不能作为首次正确率或掌握度。

## 产品主线

定位为家庭课外学习网站：孩子能自己开始一节短课，家长能知道学了什么、哪里需要帮助。首页以“继续学习、今日小任务、三科学习地图”为中心。默认单次小课建议 5–10 分钟，作为产品设计起点，后续根据使用反馈调整；允许暂停和退出。

按四个阶段规划内容，但保留启蒙及一至六年级独立筛选：

- 启蒙：语文听说与识字；数学数感、数量、图形；英语听辨、生活词汇与语音游戏。
- 一二年级：语文拼音、词句与短文；数学运算、时间、测量；英语拼读、常用表达与短故事。
- 三四年级：语文阅读理解与表达；数学多位数、分数初步和应用；英语句型、听读与分级阅读。
- 五六年级：语文篇章阅读与习作；数学分数、小数、比例、几何和数据；英语阅读、写作与综合表达。

以上是产品内容方向，不是经过审定的课标/教材映射。教材版本、学期映射要独立建模，后续在选定地区及教材后核对。不要把现有单词和识字量包装成六年级完整覆盖。首批内容以启蒙和低年级闭环验证为主，高年级显示真实筹备状态。

核心学习循环：选课 → 学一学 → 练一练 → 反馈与讲解 → 保存进度 → 后续复习。首错与最终完成分开记录，复习按知识点和错误内容安排。家长页先提供本机学习摘要，暂不引入公开排名、支付或开放式 AI 对话。

## 技术分层

继续使用现有 uni-app，逐步拆分模块，不进行全量技术栈重写。

1. 展示层：pages 与通用 components。负责布局、导航、操作反馈，不直接计算掌握度或生成复杂题目。
2. 应用层：services/curriculum、learning、review，处理选课、开始课时、提交作答、结束课时和复习。
3. 领域层：domain 中保存纯函数，包括判题、首次正确率、练习生成和进度聚合；不依赖 uni、DOM 或音频。
4. 内容层：content 中定义课程目录和旧数据适配器；现有 data JSON 保持生成链路；课程发布状态区分 draft/available，只有真实资源齐全的课可开始。
5. 平台层：platform/storage、audio、assets。存储通过接口访问，第一阶段使用 uni 本地存储；音频保留 H5 实现，未来用条件编译接入小程序/App 实现。资源地址不散落在新增页面。

建议实体：Stage、Subject、Skill、Unit、Lesson、Activity、Attempt、LessonProgress。所有内容使用稳定 ID；Lesson 引用 skillIds、activityIds，单独记录适用阶段、可选教材映射和 contentVersion。活动类型先覆盖现有词卡、听音选择、数学题，后续再增加填空、拖拽、阅读材料。

Attempt 至少记录 attemptId、sessionId、lessonId、activityId、skillIds、用户答案、正确与否、尝试次序、时间及内容版本。LessonProgress 记录完成状态、当前位置和首次答对数；不要把看过卡片直接等同掌握。按 attemptId/sessionId 去重，首次正确率分母是实际首次作答题数。中途退出与完成分别处理。

本地数据采用有 schemaVersion 的统一存储入口，处理旧版本迁移、损坏值、写入失败。第一阶段只做单个本机档案；以后添加家庭和多个孩子时，以 profileId 隔离数据。跨设备同步留在接口之后：后续增加单体 API、关系数据库存放课程与学习记录、对象存储/CDN 分发资源。同步采用追加作答事件、服务端去重、进度重新聚合，避免简单覆盖导致学习记录丢失。当前不需要微服务。

## 内容工程与多端路线

内容编辑源 → 格式与 ID 校验 → 资源生成 → 人工内容/发音核对 → 版本化课程包 → 发布。自动检查引用完整性、选项唯一性、正确答案存在、音频图片路径和年级标签合法性。新内容必须有目标、示例、练习与讲解，避免只堆题量。

先做好手机、平板和电脑 H5，再进行微信小程序技术验证，最后按真实需求评估 App。小程序前核查音频、资源体积、缓存、网络资源配置和页面兼容，补平台依赖与构建命令，并进行真机验证。不能承诺原样一键打包。离线支持也需区分本地静态服务与浏览器完整离线缓存，当前 manifest 本身不是离线验证证据。

跨端设计依据：uni-app 官方条件编译 https://zh.uniapp.dcloud.io/tutorial/platform.html 与音频 API https://zh.uniapp.dcloud.io/api/media/audio-context 。具体兼容性以目标平台构建和真机测试为准。

## 分期与验收

第一阶段：课程目录和本地学习闭环。保留所有旧入口，增加启蒙至六年级目录维度、已有内容适配、继续学习、一次练习的可靠记录和本机学习摘要。先完成三科各一条可用路径，其余真实标记未开放。完成基于纯函数的针对性测试和 H5 构建。

第二阶段：优先补齐启蒙与一二年级课程，添加讲解与错题复习。以孩子能独立完成和家长能理解报告为验收，逐步增加题型。

第三阶段：按知识点体系补齐三至六年级内容；需要人工教研审核。增加内容预览和发布工具，避免手改生成 JSON。

第四阶段：确有跨设备需求后增加家庭档案、账号与同步，再完成小程序、App 平台验证。范围不含本轮部署或发布。
